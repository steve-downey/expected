Goal

Make the generated wording the paper's wording, and make the docblocks say only what the wording needs said.

Today there are two texts. papers/expected-new.tex is what D4280 proposes, written and change-marked by hand. papers/wording/ is what specgen renders from the header docblocks, and it is the declared source of truth, but it is not what the paper shows and it is not yet draft form. Nothing checks one against the other.

The end state is:

  • the plain render of the headers is the [expected] text a working-draft pull request would carry, front matter included;
  • the paper's marked diff is a specgen render against the working draft, so it cannot lag the headers or the draft;
  • generate --validate --warnings-as-errors passes, and the notes that remain have each been read;
  • the headers carry no stand-in for something specgen could not do when they were annotated, and no second copy of text that is generated;
  • the API site built from the same docblocks reads them without warnings (api-site).

A further output is now possible and is the last stage: the draft's own utilities.tex with the paper applied, ready to open as a pull request on the draft (draft-edit).

Where this stands with specgen 0.47.0

Three things changed since the plan was last measured, and they reorder it.

**make wording fails.** Since 0.44.0 a docblock error fails the run after the output is written. The seven dead docblocks in expected<T&, E> are docblock errors, so specgen generate exits 1 on the headers as they are, with or without --validate. make wording, make wording-check and make papers all stop there for anyone with a current specgen. dead-docblocks was the third stage and is now the first.

The eight requests filed on 2026-11-18 are closed. Each was rerun here. Seven do what was asked on these headers. The eighth, a macro standing for constexpr, works on a reduced header and not on bad_expected_access.hpp, for a reason found here: the header ends with #undef BEMAN_EXPECTED_CONSTEXPR_EXCEPTION, and specgen reads the macro as it stands at the end of the translation unit. See macro-specifiers.

The plain render moved, in spelling only. Against the 0.41.1 wording of #117 it differs in 42 lines over five fragments, and all 42 are one or two of three changes: // exposition only is written // \expos, \exposidnc{name} in a listing is written \exposid{name}, and the & in the title of [expected.un.ref] is escaped. With those three normalized the two renders are the same, line for line.

Checked against specgen

The seven scratch headers from the first round of specgen issues, rerun with 0.41.1:

  • Plain comments in a class body are dropped from the synopsis, the one above an \omitted member included. A // \ref{x}, title header and a // \syn ... comment are kept.
  • A requires-clause stated as Constraints is dropped from the synopsis, and kept under \constraints-in-decl.
  • = MACRO("..."), = delete("...") and = delete all render = delete;.
  • Leading prose with \covers mandates for each asserted predicate replaces the derived ill-formed paragraph, and \synopsis-here splits the prose around the synopsis. Without the claims the derived paragraph still renders, before the prose.
  • A detached \verbatim-synopsis in a .syn section is rendered as written, with no second namespace, and a declaration after /// END is outside the section.
  • `value_ == 0` and `value == 0` both render \tcode{\exposid{value} == 0}.
  • An undescribed member in a synopsis, and a \ref header naming a section the document does not have, are validation errors that exit 1.

Still true from the first round: \seebelow noexcept masks the condition; a prose-only //! block under an \rSec renders as that section's paragraphs; an umbrella header's gathered .syn region folds each class's whole synopsis into the header synopsis.

With 0.47.0, on these headers and on a reduced one:

  • A macro whose expansion is constexpr, or nothing, is written as its expansion in a synopsis and in an item declaration, and a definition that begins with one stays with its class. Add #undef of the macro at the end of the header and it is printed under its own name again.
  • A backticked title renders \tcode{...}, with & escaped inside it.
  • \impldef{...} \ntbs{} in a docblock renders as the draft's, and the diff against the draft pairs the two.
  • A docblock error exits 1 with the output written; the last line of standard error says how many findings fail the run.

### synopsis-source

Question. Are the class synopses extracted from the class bodies, or authored with \verbatim-synopsis? Status. OPEN Recommendation. Extracted. Nothing in specgen stands in the way now. Why. Extraction is the point of the tool: an authored synopsis is a second copy of every declaration. specgen now drops from the synopsis the requires-clause it states as Constraints, which was the one thing extraction could not reach, and checks a \verbatim-synopsis against its class under --validate, which lowers the cost of the alternative. \asdraft-synopsis is a third form: the draft's synopsis text, with the specifiers taken from the declarations. It suits a class the paper barely changes, and none of the three large classes is one. Log.

### overload-partitions

Question. Where the implementation splits one specified overload into several (trivial and non-trivial, value-E and reference-E), what does the wording show? Status. OPEN Recommendation. One overload, as the paper has it: the survivor carries the wording and each twin is \merged. Why. The paper's synopsis is the specification, and the split is how this library implements it. specgen's \merge drops the conjunct that only separates a survivor from its twin, but only when the twin states the other half. The defaulted copy and move constructors here are unconstrained on purpose, so the survivor's !(A && B) has nothing to pair with and its Constraints are authored. Log.

### api-site-markup

Question. How does the API site read docblocks written for specgen? Status. OPEN Recommendation. ALIASES in docs/Doxyfile: each element tag (\effects, \constraints, \mandates, \ensures, \expects, \hardexpects) becomes a titled paragraph, and each marker (\at, \group, \also, \merge, \omit, \expos, \elsewhere) becomes nothing. Try it first: a Doxygen alias takes its arguments in braces, and \at stable.name passes its argument as the next word, so the markers that take one may need a filter in place of an alias. Why. The published pages are built from the headers by Doxygen, and that is not changing in this plan. The docblocks cannot be written for both readers by hand, so the mapping belongs in configuration. The alternatives are an INPUT_FILTER that rewrites the markers, which handles the arguments but is a second parser of the markup, and building the reference pages from specgen's own mpark or org output, which is a different site. A set of aliases that specgen shipped would serve every project that uses it, and is worth asking for once it is known to work here. Log.
